# 뇌빼고

공휴일과 주말을 이어 연차를 가장 적게 쓰고 오래 쉬는 날을 찾은 뒤, 그 연휴에 갈 곳과 하루 일정까지 짜 주는 웹 앱이다.

운영 주소는 https://noeppaego.com 이다.

제품 요구사항과 알려진 위험과 다음 단계는 [`docs/PRD.md`](docs/PRD.md)에 있다. 전체 구조와 데이터 흐름과 바깥 서비스 사용 방식은 그림과 함께 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)에 정리했다. 이 README 는 만드는 사람을 위해 동작과 실행 방법을 적는다.

## 할 수 있는 것

1. 날짜를 고른다. 한 해의 연휴를 모아 보여 주고 연차를 더 쓰면 얼마나 길어지는지도 알려 준다.
   - 연휴 목록 아래 「연휴를 내 캘린더에서 보기」에서 구독 캘린더 `/holidays.ics` 를 넣을 수 있다. 올해와 내년 연휴가 하루 종일 일정으로 들어오고 연차로 늘리는 방법은 설명에 적힌다. 만드는 코드는 `_components/holiday-ics.ts` 이고 응답은 CDN 이 하루 동안 캐시한다. 공휴일을 못 받으면 빈 캘린더 대신 503 을 돌려줘서 구독한 앱이 연휴를 지우지 않게 한다.
   - 「남은 연차로 가장 길게 쉬기」에 남은 연차 수를 넣으면 앞으로 올 연휴마다 연차를 쓸지와 몇 개 쓸지 정해서 쉬는 날 합이 가장 큰 조합을 보여 준다. 같은 날수면 연차를 덜 쓰는 쪽을 고른다. 연차 수는 주소 `?leave=` 로 받고 계산은 `calendar/domain/leave-budget.ts` 에 있다.
2. 갈 곳을 고른다. 서울과 부산과 강릉 같은 17개 출발 도시에서 닿을 만한 곳 가운데 연휴와 겹치는 축제가 많은 지역부터 추천한다.
   - 「내 위치로」를 누르면 휴대폰 위치를 출발지로 쓴다. 좌표는 소수 둘째 자리, 곧 약 1km 단위로 줄여 주소 `?from=here:위도,경도` 에만 남기고 저장하지 않는다. 출발지 이름은 카카오의 좌표 행정구역 변환으로 「종로구 근처」처럼 붙인다.
   - 거리는 차로 걸리는 시간으로 고른다. 칩은 「차로 2시간」「차로 4시간」「어디든」이다. 처음에는 연휴 길이에 맞는 칩이 골라져 있는데, 이틀 이하면 2시간이고 사흘이면 4시간이며 나흘 이상이면 어디든이다. 제주는 「어디든」을 고르고 사흘 이상일 때만 나온다. 조건에 맞는 지역은 개수 제한 없이 모두 보여 준다.
   - 지도는 상위 5곳까지 실제 도로를 그리고 나머지는 핀이나 번호표를 누를 때 그린다. 확대와 축소와 전체 보기 버튼이 있고 겹친 핀은 앞 번호에 모아 「1,2」로 보여 준다.
   - 출발 도시에서 시·군·구까지의 시간과 도로 모양은 `scripts/build-drive-routes.mjs` 로 미리 계산해서 `src/contexts/destination/infrastructure/drive-routes/` 에 둔다. 오픈스트리트맵 도로를 로컬 OSRM 으로 계산한 막히지 않을 때 기준이라서 실행 중에는 길찾기를 부르지 않는다. 카카오 길찾기와 주소 검색 결과는 저장하면 안 되므로 쓰지 않는다. 「내 위치」에서 출발하거나 표에 없는 곳은 직선 거리로 어림하고 지도에 점선으로 잇는다.
3. 일정을 본다. 관광지와 식당과 카페와 숙소를 이어 하루 일정을 짜고 지도에 동선을 그린다.
   - 식당은 카카오 「맛집」 검색 결과 중 식사 칸에서 5km 안의 가게를 많이 찾는 순서대로 고른다. 5km 안에 없을 때만 가까운 순으로 고른다. 빵집과 디저트 가게와 카페와 술집은 빼고 체인 지점도 빼며, 같은 날 저녁은 점심과 다른 메뉴부터 고른다.
   - 카페 칸은 하루 하나이고 기본은 점심 뒤다. 「여행 취향」에서 저녁 뒤로 옮기거나 뺄 수 있다. 카카오 「카페」 검색 결과를 같은 규칙으로 고르고 체인 지점과 그날 관광지로 넣은 곳은 뺀다. 카카오 키가 없으면 관광공사 음식점과 카페에서 찾는다.
   - 식당과 카페 사진은 관광공사에 같은 가게가 사진과 함께 있을 때만 붙인다. 이름이 같거나 한쪽이 다른 쪽을 품고 300m 안이면 같은 가게로 본다. 사진이 없으면 `food-emoji.ts` 의 메뉴 종류 그림을 보여 준다. 카카오는 사진을 주지 않고 이미지 검색 사진은 저작권 때문에 쓰지 않는다.
   - 「여행 취향」 시트에서 고르면 일정을 다시 짠다. 고른 것만 반영하고 고른 값은 `?with=kids&pace=relaxed` 같은 주소에 남아서 저장과 공유에도 이어진다.
     - 모두 여행 전체에 한 번 고른다.
     - 누구와: 아이와 가면 산행을 빼고 테마파크와 체험을 반긴다. 부모님과 가면 레저와 산행을 빼고 실속형 숙소를 뒤로 미룬다.
     - 속도: 여유롭게는 오후 관광을 빼고 꽉 차게는 저녁 뒤 밤 산책을 더한다.
     - 좋아하는 것: 「자연」「역사·전시」「체험·놀거리」「쇼핑·시장」 가운데 고른 종류를 먼저 넣는다.
     - 못 먹는 음식: 「해산물·회」「고기」「매운 음식」 가운데 고른 것을 모든 식사에서 꼭 뺀다.
     - 카페: 「점심 뒤」「저녁 뒤」「안 들러요」 가운데 고른다.
     - 예전 주소에는 `avoid=2026-12-25~seafood` 처럼 날짜가 붙은 값이 있다. 날짜를 떼고 읽어서 이미 공유한 링크도 열린다.
     - 볼거리 성격은 관광공사 신분류로 어림하고 음식은 카카오 분류와 상호로 어림한다. 반려동물 동반은 관광공사 반려동물 API를 신청한 뒤에 넣는다.
   - 숙소는 첫 밤 장소에서 15km 안이면 호텔과 한옥을 먼저 고르고 펜션과 그 밖의 숙소를 거쳐 모텔을 마지막에 고른다. 처음에는 매일 같은 곳에 묵고, 고른 숙소에는 카카오맵 「별점과 리뷰」 링크를 붙인다.
   - 장소마다 종류 뱃지와 한 줄 소개와 주소를 보여 준다. 주소 줄에는 복사와 지도와 주차 버튼이 있다.
     - 「지도」는 앱 밖으로 나가지 않고 지도 시트를 연다. 시트에는 핀 하나와 길찾기 버튼이 있다.
     - 「길찾기」는 카카오맵과 네이버 지도와 티맵 가운데 고르는 시트를 열고, 코드는 `navigation.ts` 에 있다. 안드로이드는 intent 주소라서 앱이 없으면 웹 길찾기로 넘어간다. 아이폰은 앱 주소를 열어 보고 1.5초 뒤에도 화면이 그대로면 웹 길찾기를 연다. PC 는 웹 길찾기를 바로 열고, 마지막으로 고른 앱은 브라우저 저장소에 기억한다.
     - 「주차」 시트는 장소 자체의 주차 안내와 500m 안의 주차장 3곳을 보여 준다. 관광공사 장소는 상세 정보의 주차 칸을 쓰고 축제는 임시 주차 안내와 축제 홈페이지를 쓰며 카카오 가게는 카카오맵 링크를 쓴다.
   - 일정 화면과 공유 화면에 「연휴엔 쉬는 가게가 많아요. 가기 전에 영업시간을 꼭 확인해 주세요.」를 한 번 보여 준다.
   - 칸마다 근처의 다른 곳으로 바꿀 수 있고 숙소도 밤마다 따로 바꾼다. 바꾼 결과는 주소 `?pick=` 에 남는다.
   - 출발 10일 안이면 기상청 예보를 붙인다. 비 오는 반나절에는 실내 장소를 고르지만 축제 칸은 그대로 둔다.
   - OpenAI 키가 있으면 하루마다 짧은 소개 글을 붙인다. 칸을 직접 바꾸거나 취향을 고른 일정에는 붙이지 않는데, 조합마다 부르면 비용이 늘기 때문이다.
4. 카카오로 로그인하면 일정을 저장하고 찜해 둘 수 있다. 저장하면 공유 페이지 `/t/{id}` 가 생긴다.
   - 로그인할 때마다 카카오 계정 고르기 화면을 띄우고 찜 화면 위에 지금 로그인한 닉네임을 보여 준다. 휴대폰과 PC가 다른 카카오 계정이면 찜 목록도 다르기 때문이다.
   - 「카톡 보내기」를 누르면 친구 선택 창이 바로 열린다. 「링크 공유」는 휴대폰에서 기본 공유 창을 열고 PC에서는 링크를 복사한다.
   - 「캘린더에 추가」는 구글 캘린더에 여행 기간을 하루 종일 일정 하나로 넣는다. 설명에는 날마다 갈 곳과 일정 링크가 들어가고 공유받은 사람도 쓸 수 있다.
   - 링크를 붙여 넣으면 메신저 미리보기에 일정 제목과 이미지가 뜨고 이미지는 `opengraph-image.tsx` 가 만든다. 공유 페이지는 검색엔진에 올리지 않는다.

## 스택

- Next.js 16 App Router 와 Turbopack, `use cache`
- React 19 와 Tailwind CSS 4
- Drizzle ORM 과 Postgres
- Vitest
- Vercel 서울 리전 `icn1`

바깥 데이터는 네 곳에서 받는다.

| 출처 | 받는 것 |
|---|---|
| 공공데이터포털 | 천문연 특일, 관광공사 국문 관광정보와 사진과 주차 안내, 기상청 단기예보와 중기예보 |
| 카카오 | 지도, 로컬 검색으로 찾는 맛집과 카페와 주차장과 동네 이름, 모빌리티 길찾기로 재는 일정 안 이동 시간, 로그인, 카카오톡 공유 |
| 오픈스트리트맵 | 갈 곳 이동 시간과 도로 모양, 시·군·구 대표 좌표. 미리 계산해 저장소에 두고 화면에 출처를 밝힌다 |
| OpenAI | 하루 소개 글. 키가 있을 때만 쓴다 |

카카오 개발자 포럼 답변을 보면 카카오 길찾기와 로컬 결과는 캐시와 보관이 금지될 수 있다. 그래서 새로 만드는 기능에서는 카카오 결과를 저장하지 않는다. 길찾기와 동네 이름은 캐시하지 않고 맛집과 카페와 주차장과 숙소 링크 검색만 몇 시간 캐시한다. 저장 일정에는 장소를 남기지 않고 열 때마다 다시 짠다. 자세한 내용은 `docs/PRD.md` 7장에 있다.

## 로컬에서 실행

Node 24 이상이 필요하다.

```bash
cp .env.example .env.local     # 아래 「환경변수」를 채운다
docker run -d --name holiday-trip-db -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=holiday_trip -p 54329:5432 postgres:17-alpine
npm install
npm run db:migrate             # .env.local 의 DATABASE_URL 에 스키마를 만든다
npm run dev                    # http://localhost:3000
```

DB 없이도 날짜와 갈 곳과 일정 화면은 뜬다. 로그인과 저장과 찜만 DB를 쓴다. Docker 를 다시 켰거나 맥을 재시작해서 DB 컨테이너가 멈췄다면 `docker start holiday-trip-db` 로 다시 켠다.

비 오는 날 화면은 실제 예보가 있어야 보인다. `.env.local` 에 `WEATHER_PREVIEW=mixed` 나 `WEATHER_PREVIEW=rain` 을 넣고 dev 서버를 다시 켜면 기상청 대신 가짜 날씨로 채운다. Vercel 에서는 이 값을 무시한다.

## 환경변수

로컬은 `.env.local` 에 넣고 배포는 Vercel 프로젝트의 Environment Variables 에 넣는다. `.env*` 는 `.gitignore` 에 있으니 키 값은 커밋하지 않는다.

| 이름 | 필요할 때 | 쓰임 |
|---|---|---|
| `DATA_GO_KR_SERVICE_KEY` | 항상 | 공공데이터포털 일반 인증키. 코드가 URL 인코딩을 하므로 「Decoding」 키를 넣는다. |
| `NEXT_PUBLIC_KAKAO_MAP_KEY` | 항상 | 카카오 JavaScript 키. 지도와 카카오톡 공유에 같이 쓴다. 브라우저에 공개되므로 카카오 콘솔에서 사이트 도메인을 제한한다. |
| `KAKAO_REST_API_KEY` | 선택 | 카카오 REST 키. 맛집과 카페 찾기, 차 이동 시간, 로그인에 쓴다. 없으면 맛집과 카페는 관광공사 음식점으로 찾고 이동은 직선 거리로만 보여 주며 로그인 버튼을 숨긴다. |
| `KAKAO_CLIENT_SECRET` | 로그인 | 카카오 콘솔 「보안 → Client Secret」. |
| `AUTH_SECRET` | 로그인 | 세션 쿠키 서명 키. `openssl rand -base64 32` 로 만든 32자 이상의 무작위 값이다. 없으면 로그인 버튼을 숨긴다. |
| `DATABASE_URL` | 저장 | Postgres 주소. 운영은 Vercel Storage 의 Neon 이 넣어 준다. |
| `OPENAI_API_KEY` | 선택 | 하루 소개 글. 서버에서만 쓰고 OpenAI 대시보드에서 월 사용 한도를 걸어 둔다. |
| `WEATHER_PREVIEW` | 로컬 전용 | `rain` 이나 `mixed`. 위 「로컬에서 실행」을 본다. |

카카오 콘솔에는 두 가지를 등록한다. 둘 다 로컬 주소 `http://localhost:3000` 과 운영 주소를 같이 넣는다.

- 「플랫폼 → Web → 사이트 도메인」에 등록한 도메인에서만 지도가 뜨고 카카오톡 공유가 보내진다.
- 로그인 Redirect URI 는 `<사이트 주소>/api/auth/kakao/callback` 이다. 받는 정보는 필수 동의로 받는 회원 번호와 닉네임뿐이다.

## 검사

```bash
npm run typecheck   # 라우트 타입 생성 + tsc
npm run lint        # ESLint(레이어 의존 규칙 포함)
npm test            # Vitest(도메인·유스케이스)
```

DB 스키마는 `src/shared/db/schema.ts` 에 있다. 바꾸면 `npm run db:generate` 로 `drizzle/` 에 마이그레이션을 만들고 `npm run db:migrate` 로 적용한다. 운영 DB 인 Neon 에 적용할 때는 그 주소를 `DATABASE_URL` 로 넣고 같은 명령을 돌린다.

## 구조

바운디드 컨텍스트마다 domain, application, infrastructure 레이어로 나눈다.

```
src/
  app/                    화면. 컨텍스트는 공개 API(index.ts)로만 부른다
    _components/          화면 조각(카드, 지도, 스켈레톤 등)
    actions.ts            서버 액션(일정 저장, 찜하기, 탈퇴)
    t/[id]/               공유 페이지와 미리보기 이미지
    api/auth/             카카오 로그인과 콜백, 로그아웃
  contexts/
    calendar/             공휴일과 연휴 계산, 남은 연차 계획
    destination/          출발지와 축제로 갈 곳 추천, 미리 계산한 도로 표
    itinerary/            하루 일정 짜기, 날씨, AI 소개, 일정 저장·공유·찜
    account/              카카오 로그인 사용자
      (컨텍스트마다 같은 모양)
      index.ts            공개 API이자 조립 루트(포트에 구현을 꽂는다)
      domain/             순수 규칙. 프레임워크와 바깥 레이어를 모른다
      application/        유스케이스. 읽기는 직렬화할 수 있는 View 로 돌려준다
      infrastructure/     포트 구현(공공데이터, 카카오, OpenAI, Drizzle)
  shared/
    kernel/               공유 커널. 좌표, 여행 기간, 날짜 표기, 한국어 조사
    public-data/          공공데이터포털 호출 공통(인증키, 거절 코드, 실패를 값으로)
    tour-api/ kma/ kakao/ 관광공사, 기상청, 카카오모빌리티 클라이언트
    db/ auth/             Drizzle 클라이언트와 스키마, 세션 쿠키
    cache.ts              바깥 응답 캐시 기간(성공은 오래, 실패는 잠깐)
scripts/                  도로 표 만들기(build-drive-routes.mjs)
docs/                     제품 요구사항(PRD.md)
```

- 의존은 `app → contexts/<x>/index → application → domain ← infrastructure` 한 방향이다. `eslint.config.mjs` 의 `no-restricted-imports` 가 거꾸로 가는 import 를 막는다.
- 컨텍스트끼리는 서로 import 하지 않는다. 화면이 calendar 의 연휴 날짜를 destination 과 itinerary 에 넘긴다.
- CQRS를 따른다. 로그인과 일정 저장과 찜하기와 탈퇴만 쓰기(Command)이고 나머지는 읽기(Query)다. 저장할 때는 화면이 보낸 일정을 믿지 않고 서버가 주소 값으로 한 번 짜 본 뒤 다시 짤 재료와 제목만 남긴다.

## 지키는 것

- 인증키는 서버에서만 쓴다. 공공데이터 URL 에는 키가 들어가므로 URL 과 에러 메시지를 로그에 남기지 않는다.
- `use cache` 함수는 실패를 던지지 않고 값으로 돌려준다. 던진 에러는 캐시 경계를 넘으면서 종류와 메시지를 잃기 때문이다.
- 바깥 API 가 실패해도 화면은 뜨고 그 정보만 빠진다. 저장하다 실패하면 일정 화면으로 돌아가 다시 저장하라고 알린다.
- 로그인이나 저장 뒤에 돌아갈 주소는 우리 사이트 안의 경로만 받는다. 이 검사는 `safeNext` 가 한다.
- 저장이나 찜 전에 계정이 아직 있는지 본다. 다른 기기에서 탈퇴한 세션은 끝내고 다시 로그인하게 한다.
- 날짜는 `2026.12.25(금)` 처럼 쓴다. 화면 문구는 해요체로 쓰고 줄표나 쉼표나 가운뎃점 대신 조사로 이으며, 조사 고르기는 `shared/kernel/korean` 이 돕는다.

## 안드로이드 앱

`android/` 는 운영 사이트를 감싸는 TWA(Trusted Web Activity) 프로젝트다. Bubblewrap 으로 만들었고 설정은 `android/twa-manifest.json` 에 있으며 패키지는 `com.hosunglee.holidaytrip` 이다. 화면은 웹과 같아서 웹을 배포하면 앱도 바뀐다.

- 앱이 주소창 없이 열리려면 `public/.well-known/assetlinks.json` 에 서명 키 지문이 있어야 한다. Play 앱 서명을 쓰면 Play Console 의 앱 서명 키 SHA-256 도 넣는다.
- 서명 키(keystore)는 저장소 밖에 두고 커밋하지 않는다.
- 스토어 등록 이미지와 스크린샷은 `store/` 에 있다.
